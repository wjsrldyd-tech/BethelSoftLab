# 가정예배서 프로젝트 기획서

## 프로젝트 개요
- **목적**: 가정예배서를 디지털로 생성하고 출력할 수 있는 데스크톱 애플리케이션
- **개발 방식**: 웹 기술(React)로 개발 후 일렉트론으로 빌드하여 배포
- **핵심 기능**: 입력 필드에 내용을 입력하면 정해진 형식(벧엘시스템 표지 스타일)으로 미리보기 및 출력

### 미리보기 영역 상세 설계

#### 탭 방식의 장점
- ✅ **공간 효율성**: 한 번에 한 페이지만 표시하여 화면이 깔끔함
- ✅ **집중도 향상**: 현재 편집 중인 페이지에 집중 가능
- ✅ **빠른 전환**: 탭 클릭으로 즉시 페이지 이동
- ✅ **데스크톱 최적화**: 고정 레이아웃으로 안정적인 사용자 경험

#### 탭 구성
```
[1] 표지  [2] 공백  [3] 경배와 찬양  [4] 고정  [5] 찬양  [6] 말씀  [7] 나눔  [8] 고정
```

#### 추가 기능
- **이전/다음 버튼**: 탭 외에 화살표 버튼으로 페이지 이동
- **키보드 단축키**: 좌우 화살표 키로 페이지 이동
- **현재 페이지 표시**: 활성 탭 하이라이트
- **페이지 번호 표시**: "1 / 8" 형식으로 현재 위치 표시
- **전체 보기 옵션**: 필요시 모든 페이지를 스크롤로 볼 수 있는 옵션 (선택)

### 입력 영역 구성 방식
- **방식 1**: 탭으로 페이지별 입력 필드 구분 (추천)
- **방식 2**: 아코디언/섹션으로 접었다 펼치기
- **방식 3**: 스크롤 가능한 단일 폼 (페이지별 구분선)

### 디자인 가이드라인 제안

#### 레이아웃
- 샘플 이미지(JPG)의 틀과 레이아웃 구조를 참고하여 동일하게 구현
- 페이지 여백, 구분선 위치, 텍스트 배치 등 샘플과 동일

#### 폰트 제안
- **한글 본문**: 
  - "나눔고딕" 또는 "Noto Sans KR" (가독성 좋음)
  - "맑은 고딕" (Windows 기본, 안정적)
- **영문/숫자**: 
  - "Inter" 또는 "Roboto" (현대적이고 깔끔)
- **제목/강조**: 
  - 본문과 동일한 폰트 사용, 크기와 굵기로 구분
- **폰트 크기**:
  - 제목: 18-24px
  - 본문: 14-16px
  - 작은 텍스트: 12px

#### 색상 제안
- **주요 텍스트**: `#2C3E50` (진한 회색-파랑, 가독성 좋음)

- **구분선**: `#BDC3C7` (연한 회색) 또는 `#E0E0E0`
- **배경**: `#FFFFFF` (흰색)
- **입력 필드 테두리**: `#95A5A6` (회색)

- **탭 활성**: `#3498DB` (파랑) 또는 `#2ECC71` (초록)

## 기능 요구사항

### 1. 입력 기능
- ✅ 실시간 입력 검증
- ✅ 필수 필드 체크 (표지 필드: 날짜, 제목, 설교제목)
- ✅ 텍스트 길이 제한 (선택)
- ✅ 날짜 형식 검증
- ✅ 이미지 업로드 (표지그림, 악보이미지, 말씀 이미지) - 로컬 파일만 지원
  - **HDD에 저장된 파일 선택 가능**: HTML5 `<input type="file">` 사용
  - 사용자가 자신의 컴퓨터(HDD, USB 등)에서 파일 선택
  - 파일 탐색기 창이 열려서 원하는 이미지 파일 선택 가능
  - 지원 형식: JPG, PNG, GIF 등 일반 이미지 형식
- ✅ 이미지 미리보기 및 크기 조정

### 2. 미리보기 기능
- ✅ 실시간 미리보기 업데이트
- ✅ 입력 내용 즉시 반영
- ✅ **페이지 탭 전환 방식** (한 번에 한 페이지만 표시)
- ✅ 탭 클릭 또는 이전/다음 버튼으로 페이지 이동
- ✅ 키보드 단축키 지원 (좌우 화살표 키)
- ✅ 현재 페이지 번호 표시 (예: "1 / 8")
- ✅ A4 비율로 페이지 미리보기
- 💡 전체 보기 옵션 (모든 페이지를 스크롤로 보기 - 선택 기능)

### 3. 출력 기능
- ✅ **PDF 다운로드** (추천)
  - 장점: 
    - 구현이 간단하고 안정적
    - PDF는 어디서든 열 수 있어 호환성 좋음
    - 사용자가 원하는 프린터로 자유롭게 출력 가능
    - 파일로 보관 및 공유 가능
  - 기술: jsPDF + html2canvas 또는 react-pdf
- 💡 **브라우저 인쇄 기능** (선택)
  - 장점: 추가 구현 불필요
  - 단점: 브라우저마다 출력 결과가 다를 수 있음
  - 추천: PDF 다운로드 후 사용자가 직접 인쇄하는 방식이 더 안정적

### 4. 저장 및 불러오기 기능

#### 4-1. 예배별 파일 저장 (한글 문서처럼)
- ✅ **예배서 파일로 저장**
  - 각 예배를 독립적인 파일로 저장 (예: "2024-01-15_가정예배.json")
  - HDD에 원하는 위치에 저장 가능
  - 파일명에 날짜/제목 포함하여 관리 용이
  - 한글 문서처럼 예배별로 파일 단위 관리

#### 4-2. 저장된 파일 불러오기
- ✅ **JSON 파일 불러오기 (Import)**
  - 저장한 JSON 파일을 선택하여 불러오기
  - 파일 탐색기에서 직접 선택
  - JSON에 저장된 이미지 경로에서 자동으로 이미지 로드
  - 경로에 파일이 없으면 사용자에게 알림 및 재선택 요청
  - 불러온 데이터로 예배서 내용 복원
  - 수정 후 다시 저장 가능

#### 4-3. 로컬 스토리지 (자동 저장)
- ✅ **자동 저장**
  - 입력 중인 내용을 브라우저 로컬 스토리지에 자동 저장
  - 페이지 새로고침 후에도 최근 작업 내용 유지
  - 임시 저장 용도

#### 4-4. 저장된 예배서 목록 관리
- ✅ **예배서 목록**
  - 로컬 스토리지에 저장된 예배서 목록 표시
  - 날짜, 제목으로 검색 및 필터링
  - 목록에서 선택하여 불러오기
  - 삭제 기능

#### 사용 시나리오
```
1. 예배서 작성 완료
   ↓
2. "파일로 저장" 클릭
   ↓
3. 파일명 입력: "2024-01-15_새해를_시작하며"
   ↓
4. JSON 파일로 저장
   - 예: "2024-01-15_새해를_시작하며.json"
   - 텍스트 데이터 + 이미지 경로만 저장
   ↓
5. HDD 원하는 폴더에 저장
   ↓
6. 나중에 "파일 불러오기" 클릭
   ↓
7. 저장한 JSON 파일 선택
   ↓
8. JSON에 저장된 경로에서 이미지 자동 로드
   - 경로에 파일이 없으면 사용자에게 알림
   ↓
9. 예배서 내용 복원 → 수정 가능 → 다시 저장
```

#### 파일 형식 및 이미지 처리

**저장 방식: JSON 파일 (벧엘시스템 방식) ⭐**
- JSON 파일로 모든 텍스트 데이터 저장
- 이미지는 경로(전체 경로)만 JSON에 저장
- 이미지 파일은 원본 위치에서 그대로 사용

**JSON 파일 구조 예시:**
```json
{
  "date": "2024-01-15",
  "title": "새해를 시작하며",
  "sermonTitle": "순종으로 경험하는 기적 (마태복음 8:5-13)",
  "coverImage": "C:\\Users\\사용자\\Documents\\악보\\표지.jpg",
  "hymn1Image": "C:\\Users\\사용자\\Documents\\악보\\찬양1.jpg",
  "hymn2Image": "C:\\Users\\사용자\\Documents\\악보\\찬양2.jpg",
  "prayerContent": "기도 내용...",
  "sermonTitle": "말씀 제목...",
  "sermonContent": "말씀 내용...",
  "sermonImage": "C:\\Users\\사용자\\Documents\\이미지\\말씀.jpg",
  "sharing1": "나눔1 내용...",
  "sharing2": "나눔2 내용...",
  "closingPrayer": "마침기도 내용..."
}
```

**장점:**
- ✅ JSON 파일 크기가 매우 작음 (텍스트 + 경로만)
- ✅ 이미지는 원본 품질 그대로 사용
- ✅ 이미지 파일을 별도로 복사할 필요 없음
- ✅ 벧엘시스템과 동일한 방식으로 익숙함
- ✅ 간단하고 직관적

**불러오기 시:**
- JSON 파일 선택
- JSON에 저장된 경로에서 이미지 자동 로드
- 경로에 파일이 없으면 사용자에게 알림 및 재선택 요청

### 플랫폼 선택: 웹 vs 일렉트론

#### 비교 분석

| 항목 | 웹 애플리케이션 | 일렉트론 |
|------|---------------|---------|
| **개발 난이도** | ⭐⭐ 쉬움 | ⭐⭐⭐ 보통 |
| **배포** | ⭐⭐⭐ 매우 쉬움 (URL 공유) | ⭐⭐ 보통 (설치 파일 배포) |
| **업데이트** | ⭐⭐⭐ 자동 (서버 업데이트만) | ⭐⭐ 사용자가 직접 업데이트 |
| **크로스 플랫폼** | ⭐⭐⭐ 모든 OS (브라우저만) | ⭐⭐⭐ Windows/Mac/Linux |
| **파일 접근** | ⭐⭐ 제한적 (업로드/다운로드) | ⭐⭐⭐ 자유로운 파일 시스템 접근 |
| **오프라인** | ⭐⭐ PWA로 가능 | ⭐⭐⭐ 완전 오프라인 |
| **성능** | ⭐⭐⭐ 빠름 | ⭐⭐ 보통 (브라우저 엔진 사용) |
| **용량** | ⭐⭐⭐ 작음 (서버) | ⭐⭐ 큼 (100MB+) |
| **보안** | ⭐⭐⭐ 브라우저 샌드박스 | ⭐⭐ 시스템 접근 가능 (주의 필요) |

#### 이 프로젝트에 적합한 방식: **하이브리드 접근법** ⭐ 추천

**개발 및 테스트: 웹 애플리케이션**
- 빠른 개발 및 테스트
- 브라우저에서 즉시 확인 가능
- 핫 리로드로 빠른 반복 개발

**배포: 일렉트론으로 빌드**
- 웹 코드를 그대로 사용하여 일렉트론 앱으로 빌드
- 폴더 관리가 편리함 (파일 시스템 직접 접근)
- JSON 파일 저장/불러오기가 간단하고 직관적
- 완전한 오프라인 사용 가능
- 네이티브 앱처럼 사용 가능

**장점:**
1. ✅ **개발 효율성**: 웹으로 빠르게 개발 및 테스트
2. ✅ **폴더 관리**: 일렉트론 빌드로 파일 시스템 자유롭게 접근
3. ✅ **사용자 경험**: 네이티브 앱처럼 사용 가능
4. ✅ **코드 재사용**: 웹 코드를 그대로 일렉트론에서 사용
5. ✅ **배포 유연성**: 필요시 웹 버전도 함께 제공 가능

**결론**: 
- **개발 단계**: 웹 애플리케이션으로 개발 및 테스트
- **배포 단계**: 일렉트론으로 빌드하여 데스크톱 앱으로 배포
- **최종 형태**: 일렉트론 데스크톱 애플리케이션
